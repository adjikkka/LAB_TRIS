## 1. Цель

Отделить интерфейс от источника данных: список и форма вызывают функции
API-модуля (`getTickets`, `createTicket`), умеют ждать ответ и показывают
четыре состояния (loading / empty / data / error). Повторная отправка
не создаёт дубликат; `id` и `number` приходят из ответа, а не считаются
на клиенте.

## 2. Что сделали

1. Создали `frontend/.env.example` с `VITE_API_BASE_URL=http://localhost:5000`
   и `VITE_USE_MOCK=true`; `.env` добавлен в `.gitignore` и в Git не попадает.
   После изменения `.env` перезапускали `npm run dev`.
2. Написали `src/api/mockTickets.js`: задержка 500 мс, учебный флаг
   `force500` возвращает 500, короткая тема → 400, нормальное создание →
   201 с серверными `id`, `number` (`ОБР-2026-…`), `status: 'New'`.
3. Написали `src/api/tickets.js`: экспортирует `getTickets` и
   `createTicket`; переключатель источника `VITE_USE_MOCK` читается
   в одном файле; реальная ветка использует встроенный `fetch`
   (axios не ставили). URL знает только API-модуль, страницы его не импортируют.
4. В `src/api/http.js` выделили общую HTTP-часть: проверка `response.ok`
   (коды 400/500 — это ветка `!ok`, а не `catch`), сетевой сбой ловится
   в `catch` и не подменяется кодом 500.
5. Список перевели на асинхронную загрузку (`onMounted`): одно поле
   состояния `screen` со значениями `loading | empty | data | error`,
   взаимоисключающие `v-if` / `v-else-if` / `v-else`.
6. Форму перевели на `createTicket`: результат (запись) берётся целиком
   из ответа; при отказе поля остаются заполненными, чтобы исправить ввод.
7. Защита от двойной отправки: `if (isSubmitting.value) return`,
   флаг ставится перед запросом и снимается в `finally`; кнопка
   `:disabled="isSubmitting"` и текст «Создаём…».
8. Воспроизвели три отказа и дали им разные тексты (см. раздел 3).

## 3. Чеклист трёх отказов

| Отказ | Как воспроизвести | Техническая ветка | Текст человеку | Скрин |
|-------|-------------------|-------------------|----------------|-------|
| 400 | тема из 3 символов | `!ok`, status 400 | «Проверьте поля формы. Тема: от 5 до 80 символов» | (место для скрина) |
| 500 | включить `force500` в `mockTickets.js` | `!ok`, status 500 | «Сервер не смог обработать запрос» | (место для скрина) |
| Нет связи | `VITE_USE_MOCK=false`, API не запущен | `catch`, ответа нет | «Нет связи с сервером. Проверьте, что API запущен по адресу http://localhost:5000» | (место для скрина Network с неуспешной попыткой на порт 5000) |

Ветка Network: в режиме mock HTTP-запроса нет — это ожидаемо; для сценария
«нет связи» F12 → Network → Fetch/XHR показывает неуспешную попытку к
`http://localhost:5000/api/tickets`.

*Место для скрина: успешный POST и один отказ в Network (или согласованная
замена «mock без HTTP»).*

## 4. Доказательство успеха

- Список при входе на `/`: сначала «Загрузка…» (mock с задержкой 500 мс),
  затем таблица; при пустом ответе — «Обращений пока нет», это отличное
  от загрузки состояние.
- Успешное создание: запись добавлена, `id` и `number` — из ответа мока;
  двойной клик по кнопке во время запроса создаёт одну запись.
