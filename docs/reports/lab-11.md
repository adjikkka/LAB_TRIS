## 1. Цель

Гость не создаёт обращения (401), исполнитель не двигает чужое (403),
назначение и смена статуса — разные права. Пароль — хэш библиотеки,
а не открытый текст. Опасный HTML в описании показывается текстом,
не выполняется.

## 2. Что сделали

1. Выбрали **один** способ входа — учебный JWT в заголовке
   `Authorization: Bearer …` (записано в README; cookie-сессии не смешиваются).
2. Добавили в модель пользователя `login`, `role`, `password_hash`
   (миграция применена). Пароли хэшируются `PasswordHasher` из
   ASP.NET Identity (PBKDF2 с солью) — не Base64 и не самописный хэш.
3. `POST /api/auth/login` (`backend/Controllers/AuthController.cs`):
   проверяет логин и хэш, возвращает JWT с claims
   (`NameIdentifier`, `Name`, `Role`). Неверные данные — 401.
4. Защитили API: `POST /api/tickets` и `PATCH …/assignee` — только
   роль «Комендант» (исполнителю 403, гостю 401);
   `PATCH …/status` — для исполнителя сравнивается
   `ticket.AssigneeUserId == userId` (чужая запись → 403).
   Спрятанная кнопка не заменяет серверную проверку — проверки в сервисе.
5. Список по ТЗ: комендант видит все обращения, исполнитель — только
   назначенные на него (фильтр в `TicketService.GetTicketsAsync`).
6. Экран `/login` отправляет тот же вход (`src/services/auth.js` +
   `src/api/auth.js`); токен и данные пользователя сохраняются в
   localStorage (для учебного контура допустимо), шапка показывает
   «кто вошёл», есть кнопка «Выйти».
7. Матрица ролей оформлена в `/docs/role-matrix.md` по образцу курса —
   со своими ролями и путями API.
8. Проверили XSS: описание со `<script>alert(1)</script>` выводится
   интерполяцией Vue `{{ }}` — на экране виден текст, `alert` не всплывает,
   `v-html` не используется.
9. `git grep -i password` и `git grep -i secret` не находят реальных
   секретов (учебные пароли учёток — в README, как разрешает методичка).

## 4. Доказательство входа через UI

Вошли как `komendant` через экран `/login` — в Network виден успешный
`POST /api/auth/login` (200, token в ответе), затем создание обращения
прошло (201). Не вошедший пользователь получает на создание 401.

*(место для скрина: Network — POST /api/auth/login 200)*
