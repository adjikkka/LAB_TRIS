## 1. Цель

Схема PostgreSQL под проект: три таблицы со связями (справочник комнат,
пользователи, обращения), CHECK на четыре статуса, учебные данные во всех
статусах и запросы с фильтром, сортировкой, `JOIN` и `GROUP BY`.
Entity Framework на этой работе не используется — сдача три SQL-файла в `/db`.

## 2. Что сделали

1. Установили PostgreSQL, подключились через `psql`/pgAdmin.
2. Создали отдельную учебную базу (не служебную `postgres`):
   `createdb dorm_tickets`.
3. `db/schema.sql` — таблицы `rooms`, `users`, `tickets`:
   - первичные ключи `id` (`GENERATED BY DEFAULT AS IDENTITY`);
   - внешние ключи `room_id → rooms(id)`, `created_by_user_id → users(id)`,
     `assignee_user_id → users(id)` с `ON DELETE RESTRICT`;
   - `CHECK (status IN ('New', 'InProgress', 'Closed', 'Cancelled'))`;
   - уникальный номер обращения (`number`);
   - индексы с комментариями «зачем»: `tickets_status_idx`,
     `tickets_room_id_idx`, `tickets_assignee_user_id_idx`.
4. Схема запускается повторно: в начале скрипта `DROP TABLE IF EXISTS … CASCADE`
   (учебное пересоздание, не операция приложения).
5. `db/seed.sql`: 3 пользователя (комендант, сантехник, электрик), 4 комнаты,
   7 обращений во всех четырёх статусах; после вставки счётчики `id`
   сдвинуты `setval`, чтобы API продолжал нумерацию без конфликтов.
   Паролей в файле нет: в `password_hash` — хэш PBKDF2 (формат ASP.NET
   Identity, ЛР11).
6. `db/queries.sql` — обязательные запросы 1–3 и два дополнительных.

## 3. Обязательные запросы и результаты

*(Результаты приведены по данным seed; при прогоне добавьте скрины psql/pgAdmin.)*

### 3.1. Фильтр и сортировка

```sql
SELECT number, title, status, created_at
FROM tickets
WHERE status = 'New'
ORDER BY created_at DESC;
```

Ожидание: ОБР-2026-005 и ОБР-2026-001 — обе строки в статусе `New`.

### 3.2. JOIN

```sql
SELECT t.number, t.title, r.name AS room_name, t.status
FROM tickets AS t
JOIN rooms AS r ON r.id = t.room_id
ORDER BY t.created_at DESC;
```

Ожидание: 7 строк, в столбце `room_name` — «Комната 305», «Комната 203»,
«Комната 410», «Комната 111» — название справочника, а не только id.

### 3.3. GROUP BY

```sql
SELECT status, COUNT(*) AS count
FROM tickets
GROUP BY status
ORDER BY status;
```

Ожидание: `Cancelled 1`, `Closed 2`, `InProgress 2`, `New 2` — все четыре
группы видны.

### 3.4. Проверка CHECK

```sql
INSERT INTO tickets (number, title, description, status, room_id, created_at, created_by_user_id)
VALUES ('ОБР-2026-999', 'Проверка CHECK', 'Строка для проверки ограничения статуса', 'Done', 1, now(), 1);
```

Ожидание: PostgreSQL отклоняет вставку ошибкой CHECK
(`violates check constraint "tickets_status_check"`). Ошибочная вставка
в seed не оставлена — строка закомментирована.
