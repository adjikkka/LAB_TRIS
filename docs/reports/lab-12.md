## 3. Обязательный сценарий

1. Комендант входит (`komendant`).
2. Создаёт обращение **на экране** `/new`, не в Swagger.
3. Назначает исполнителя (сантехника).
4. Исполнитель входит вторым пользователем (`santehnik`).
5. Ставит статус `InProgress`.
6. Один `id` виден в UI, Network и SQL.
7. После рестарта API запись остаётся.

## 4. Один id как доказательство

После создания записать:

```text
id = ________ · number = ОБР-2026-________
```

| Где | Что показать | Факт |
|-----|--------------|------|
| UI | строка таблицы с номером и статусом | |
| Network | `POST /api/tickets` → 201, `id` в Response | |
| SQL | `SELECT id, number, title, status, assignee_user_id FROM tickets WHERE id = …;` | |
| после рестарта | `GET /api/tickets/{id}` возвращает ту же запись | |

*Столбец «Факт» и значения id заполните при прогоне на своей машине.*
