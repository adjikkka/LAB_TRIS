# Матрица ролей (ЛР11)

Тема: **Система обработки обращений жильцов общежития**.
Роли взяты из ТЗ ЛР1 (`docs/lab-01-requirements.md`, раздел 5) и заявки
на тему (`docs/project-proposal.md`, раздел 3): Комендант, Сантехник,
Электрик. Пути API — из API-контракта ЛР2 (`docs/api-contract.md`).

## Учебные учётки

| Логин | Роль | Пароль (учебный, разрешено указывать в README) |
|-------|------|------------------------------------------------|
| `komendant` | Комендант (создаёт, назначает, отменяет) | `Passw0rd!` |
| `santehnik` | Сантехник (меняет статус **своих**) | `Passw0rd!` |
| `elektrik`  | Электрик (меняет статус **своих**) | `Passw0rd!` |

В PostgreSQL в столбце `password_hash` хранится **хэш** (PBKDF2, формат
ASP.NET Identity v3), а не текст `Passw0rd!`. Способ входа — **один**:
учебный JWT в заголовке `Authorization: Bearer …` (POST `/api/auth/login`).

## Матрица «роль × действие»

| Действие | Комендант | Сантехник / Электрик | Гость (не вошёл) |
|----------|-----------|----------------------|------------------|
| `POST /api/tickets` — создать | да → 201 | нет → 403 | нет → 401 |
| `PATCH …/assignee` — назначить | да, только в статусе New (иначе 409) | нет → 403 | нет → 401 |
| `PATCH …/status` → `InProgress` | нет → 403 | да, **если** он назначен (`assigneeUserId == userId`) | нет → 401 |
| `PATCH …/status` → `Closed` | нет → 403 | да, только после `InProgress` (иначе 409) | нет → 401 |
| `PATCH …/status` → `Cancelled` | да, только из `New` (иначе 409) | нет → 409 (переход не разрешён) | нет → 401 |
| `PATCH …/status` чужой записи | — | нет → 403 | нет → 401 |
| `GET /api/tickets` — список | да (все) | нет → только свои (фильтр по `assigneeUserId`) | нет → 401 |
| `GET /api/tickets/{id}` чужой записи | да | нет → 403 | нет → 401 |

Правила процесса (в коде — `backend/Services/TicketService.cs`):

- назначить исполнителя можно только в статусе `New` → иначе **409**;
- перевести в `InProgress` можно только при назначенном исполнителе → иначе **409**;
- исполнитель меняет статус только своего обращения → иначе **403**;
- запрещённый переход статуса (например `New → Closed`) → **409**;
- комендант не меняет рабочий статус, он отменяет обращение → иначе **403**.

## 401 и 403 в этой системе

| Код | Когда | Пример |
|-----|-------|--------|
| **401** | сервер не установил личность | `POST /api/tickets` без заголовка `Authorization` |
| **403** | личность известна, действие запрещено | сантехник назначает исполнителя; исполнитель двигает чужую запись |

## Доказательства на сдаче

| Проверка | Ожидание | Где смотреть |
|----------|----------|--------------|
| `POST /api/tickets` без входа | 401 | Swagger / коллекция («05») / Network |
| Электрик назначает исполнителя | 403 | коллекция («14») |
| Сантехник меняет статус чужой записи | 403 | Swagger / коллекция |
| Комендант ставит `InProgress` | 403 | коллекция («13») |
| Вошёл сантехник → своё `InProgress` | 200 | коллекция («11») |
| `POST` без входа и после входа | 401, затем 201 | Swagger |
| Столбец `password_hash` в БД | длинный хэш, не `Passw0rd!`, не Base64 пароля | pgAdmin / psql |
| Описание со `<script>alert(1)</script>` | текст на экране Vue, без `alert` | UI, список обращений |

## Безопасный вывод

Пользовательский текст выводится только интерполяцией Vue
(`{{ item.title }}`, `{{ item.description }}`) — `v-html` не используется.
`<script>` в описании показывается как текст, не выполняется.

## Чем не копия соседа

В матрице — роли и предметная область этой темы (комендант общежития,
сантехник и электрик), пути API из ЛР2 (`/api/tickets`, `…/assignee`,
`…/status`) и правила из ТЗ ЛР1: комендант создаёт и назначает, но не
меняет рабочий статус; исполнители видят только свои обращения.
