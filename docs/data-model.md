# Модель данных

## 1. Словарь терминов

| Термин курса | Термин моей темы |
| :--- | :--- |
| Ticket | Обращение |
| Site | Комната |
| User | Пользователь |

В технической части проекта для главной сущности используется имя `Ticket`, 
а в пользовательском интерфейсе и документации предметной области — «Обращение».

## 2. Главная сущность — Ticket

Главная сущность системы — обращение жильца о бытовой неполадке.

Основные поля:

| Поле | Назначение |
| :--- | :--- |
| id | Числовой первичный ключ |
| number | Человеческий номер обращения |
| title | Заголовок обращения |
| description | Описание проблемы |
| status | Текущий статус обращения |
| roomId | Внешний ключ на комнату |
| createdByUserId | Внешний ключ на пользователя, создавшего обращение |
| assigneeUserId | Внешний ключ на назначенного исполнителя |

Статусы обращения:

- `New` — новое обращение;
- `InProgress` — обращение находится в работе;
- `Closed` — обращение закрыто;
- `Cancelled` — обращение отменено.

## 3. Справочник — Room

Справочник комнат содержит:

| Поле | Назначение |
| :--- | :--- |
| id | Числовой первичный ключ |
| name | Название или номер комнаты |

В сущности `Ticket` хранится только `roomId`.
Название комнаты не дублируется в каждом обращении.

## 4. Пользователь — User

Пользователь системы содержит:

| Поле | Назначение |
| :--- | :--- |
| id | Числовой первичный ключ |
| name | Имя пользователя |

Пользователь может создавать обращения и может быть назначен исполнителем.

## 5. Связи между сущностями

- Одна комната может иметь много обращений.
- Одно обращение относится к одной комнате.
- Один пользователь может создать много обращений.
- Одно обращение создаётся одним пользователем.
- Один пользователь может быть назначен исполнителем нескольких обращений.
- У нового обращения исполнитель может отсутствовать.

## 6. Проверка 3НФ

Название комнаты хранится в сущности `Room` только один раз.
В `Ticket` хранится только внешний ключ `roomId`.

При переименовании комнаты изменяется одна запись в `Room`, поэтому
название комнаты не дублируется в обращениях.

Таким образом, данные о комнате отделены от обращений, а в обращении
используется внешний ключ `roomId`.

## 6. Проверка 3НФ

Название комнаты хранится в сущности `Room` один раз.
В сущности `Ticket` хранится только внешний ключ `roomId`.

Например, если комната имеет номер `305`, то значение `305` не записывается
в каждом обращении. В обращении хранится только `roomId`, который ссылается
на соответствующую запись в `Room`.

При изменении номера комнаты изменяется одна запись в таблице `Room`.
Поэтому название комнаты не дублируется в обращениях.

Таким образом, данные о комнате отделены от данных обращения, а связь между
ними осуществляется с помощью внешнего ключа `roomId`.

## 7. ER-модель

Основные сущности системы:

- `User` — пользователь системы;
- `Room` — комната общежития;
- `Ticket` — обращение жильца.

Связи между сущностями:

- один пользователь может создать много обращений;
- одно обращение создаётся одним пользователем;
- один пользователь может быть назначен исполнителем многих обращений;
- одно обращение может иметь одного исполнителя;
- одна комната может содержать много обращений;
- одно обращение относится к одной комнате;
- исполнитель для нового обращения может отсутствовать.

```mermaid
erDiagram
    USER ||--o{ TICKET : "создаёт"
    USER o|--o{ TICKET : "исполняет"
    ROOM ||--o{ TICKET : "содержит"

    USER {
        int id PK
        string name
    }

    ROOM {
        int id PK
        string name
    }

    TICKET {
        int id PK
        int number
        string title
        string description
        string status
        int roomId FK
        int createdByUserId FK
        int assigneeUserId FK
    }
