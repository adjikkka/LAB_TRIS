# Матрица требований

Матрица связывает требования лабораторной работы 1 с сущностями и полями
модели данных, а также с HTTP-запросами API.

| Требование ЛР1 | Поле или сущность | Запрос API | Критерий |
| :--- | :--- | :--- | :--- |
| Создать обращение | `Ticket.title`, `Ticket.roomId`, `Ticket.description` | `POST /api/tickets` | 1 |
| Назначить исполнителя | `Ticket.assigneeUserId` | `PATCH /api/tickets/{id}/assignee` | 2 |
| Перевести обращение в работу | `Ticket.status` | `PATCH /api/tickets/{id}/status` | 3 |

## Связь с критериями ЛР1

### Критерий 1 — создание обращения

Пользователь вводит заголовок, комнату и описание проблемы.
Клиент отправляет данные запросом `POST /api/tickets`.
После успешного создания сервер устанавливает идентификатор, номер и начальный
статус `New`.

### Критерий 2 — назначение исполнителя

Комендант выбирает пользователя, который будет выполнять обращение.
Идентификатор выбранного пользователя записывается в поле `assigneeUserId`.
Для изменения используется отдельный запрос
`PATCH /api/tickets/{id}/assignee`.

### Критерий 3 — перевод обращения в работу

После назначения исполнителя обращение может быть переведено из статуса
`New` в `InProgress`.
Для изменения статуса используется отдельный запрос
`PATCH /api/tickets/{id}/status`.
