# Приёмочные проверки (ЛР12)

Тема: **Система обработки обращений жильцов общежития**.
Стенд: Vue `http://localhost:5173` → ASP.NET Core `http://localhost:5000`
→ PostgreSQL (обычно порт 5432).

## 1. Обязательный сценарий

1. Комендант входит (`komendant` / учебный пароль из README).
2. Создаёт обращение через UI на `/new` (не в Swagger).
3. Назначает исполнителя (сантехника) на обращение в статусе `New`.
4. Исполнитель входит вторым пользователем (`santehnik`).
5. Ставит статус `InProgress` на своё обращение.
6. Один и тот же `id` виден в UI, Network и SQL.
7. API перезапускают — запись остаётся в базе.

## 2. Один id как доказательство

После создания запишите и используйте **один** id во всех проверках:

```text
id = ________ · number = ОБР-2026-________
```

| Где | Что показать |
|-----|--------------|
| UI | строка или карточка с номером обращения и статусом |
| Network | `POST /api/tickets` → код 201, `id` и `number` в Response |
| SQL | `SELECT id, number, title, status, assignee_user_id FROM tickets WHERE id = …;` |
| после рестарта API | `GET /api/tickets/{id}` (или обновление списка) возвращает ту же запись |

Не показывать три разные записи: mock, Swagger и старую строку seed.

## 3. Таблица трёх критериев ЛР1

| Критерий | Дано | Когда | Что ждали | Куда смотреть (экран) | Запрос API | Где в SQL | Факт |
|----------|------|-------|-----------|------------------------|------------|-----------|------|
| 1. Создать | комендант вошёл | заполнил форму: тема 5–80, комната, описание 10–500, «Создать» | POST 201, запись со статусом `New` и номером | таблица на `/` показывает новое обращение | `POST /api/tickets` | строка в `tickets` с `status = 'New'` | |
| 2. Назначить | обращение в статусе `New` | комендант выбрал исполнителя отдельным действием | `assigneeUserId` записан, статус не изменился | строка обновилась (исполнитель) | `PATCH /api/tickets/{id}/assignee` | `assignee_user_id` в строке того же `id` | |
| 3. В работу | вошёл назначенный исполнитель | выбрал `InProgress` | статус изменён на `InProgress` | статус в таблице | `PATCH /api/tickets/{id}/status` | `status = 'InProgress'` у того же `id` | |

Для каждого критерия привести: экран, запрос Network, строку PostgreSQL
и результат после рестарта, если применимо. Столбец «Факт» заполняется
при прогоне.

## 4. Защита и сохранность (для демо)

| Проверка | Как | Ожидание |
|----------|-----|----------|
| Гость не создаёт | `POST /api/tickets` без `Authorization` | 401 |
| Чужое не двигается | исполнитель на запись другого исполнителя | 403 |
| Сохранность | `Ctrl+C`, снова `dotnet run`, GET по id | запись на месте |

## 5. Порты и настройки

| Узел | Адрес |
|---|---|
| Vue | `http://localhost:5173` |
| ASP.NET Core | `http://localhost:5000` |
| PostgreSQL | `localhost:5432` |

Frontend: `.env` содержит ровно
`VITE_API_BASE_URL=http://localhost:5000` и `VITE_USE_MOCK=false`;
после изменения `.env` — перезапуск `npm run dev`.

## 6. Признаки CORS-проблемы

- запрос виден в Network, но браузер не отдаёт ответ приложению;
- Swagger на API работает;
- в консоли есть сообщение CORS.

Решение: политика `Frontend` в `backend/Program.cs` разрешает именно
`http://localhost:5173`.
